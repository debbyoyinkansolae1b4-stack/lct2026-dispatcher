# Помощник диспетчера — ЛЦТ2026, задача 3 «Билайн Бизнес»

Веб-прототип для диспетчера выездных инженеров. Он распределяет заявки дня между бригадами с учётом навыков,
транспорта, смен, временных окон и пробок, строит маршруты и показывает их на карте. Если в течение дня что-то
меняется (поступила авария, заявку отменили, инженер выбыл), помощник перестраивает план за несколько секунд и не трогает
уже начатые работы. По любой заявке можно спросить, почему она досталась именно этой бригаде.

В основе — расширяемый движок планирования. Правила и оценка плана описаны в коде предметной области, поэтому модель
растёт вместе с правилами бизнеса. Гибридный поиск сочетает быстрый эволюционный поиск и графовую нейросеть, которая
учится прямо на задаче дня. Каждый план проходит независимую проверку всех правил, а диспетчер и руководитель управляют
приоритетами, бюджетом и составом поиска из интерфейса.

Команда «Эксперимент»: Яцков Михаил Сергеевич (капитан, разработчик), Хайруллин Альвар Артурович (разработчик).

## Результат на данных задания

Три участка Москвы, 17 августа, 205 заявок:

| Показатель | Наш план | Для сравнения |
|---|---|---|
| Выполнено заявок | 204 из 205 | базовый вариант из ТЗ — 160 из 205 |
| Бригад на линии | 25 из 35 доступных | базовый вариант из ТЗ — 34 |
| Пробег | 1 102 км | базовый вариант из ТЗ — 2 021 км |
| Время расчёта | 20 с на план дня, 6 с на перестройку после события | |

Одну заявку на Юго-востоке не удаётся поставить в её временное окно. В сравнении
с OR-Tools на тех же данных, в одинаковых условиях, с одинаковым временем и числом процессов наш план лучше по порядку
приоритетов (сначала меньше бригад, затем пробег) во всех трёх участках: все решатели назначают все заявки, на двух участках
у нас на бригаду меньше при большем пробеге, на третьем пробег короче.

Расчёт выполнен 26.09.2026 с настройками по умолчанию на 4 процессах поиска (Apple M4 Pro). Поиск ограничен временем,
поэтому на машине с более медленными ядрами за те же 20 секунд он успевает меньше и пробег может получиться больше.
Подробности — в разделе 7 документации.

## Установка и запуск

Нужны Python 3.11 или новее (проверено на 3.13), 4 ядра и около 4 ГБ свободной памяти: по умолчанию план считают
4 процесса поиска одновременно.

### Локально

    git clone https://github.com/debbyoyinkansolae1b4-stack/lct2026-dispatcher.git dispatcher && cd dispatcher
    python3 -m venv .venv
    .venv/bin/pip install -r requirements.txt
    .venv/bin/uvicorn app:api --port 8000

Откройте http://127.0.0.1:8000. После запуска приложению нужно от нескольких секунд до полуминуты, в зависимости от
машины: оно заранее прогревает процессы поиска. При первом запуске на машине дополнительно компилируются ядра поиска,
это происходит один раз. В Windows вместо `.venv/bin/` пишите `.venv\Scripts\`.

### В Docker

В папке репозитория:

    docker build -t dispatcher .
    docker run --rm -p 8000:8000 dispatcher

Откройте http://127.0.0.1:8000. Образ собирается несколько минут: в него входят Python 3.13 и torch для процессора
(без видеокарты), а при сборке выполняется короткий расчёт, который заранее компилирует ядра поиска. Если ограничиваете
память контейнера (`--memory`), дайте не меньше 4 ГБ. На машине, где меньше 4 ядер, уменьшите число процессов поиска
в настройках (`/admin`, вкладка «Поиск»).

### На сервере

Подойдёт любой Linux-сервер с Docker, у которого, как и для локального запуска, 4 ядра и 4 ГБ свободной памяти. Лучше
выделенные ядра: на виртуальных ядрах, которые сервер делит с соседями, поиск успевает за то же время меньше и план
получается хуже.

1. Установите Docker по инструкции для своей системы: https://docs.docker.com/engine/install/. На Ubuntu и Debian
   достаточно команды `curl -fsSL https://get.docker.com | sudo sh`.
2. Скачайте репозиторий и соберите образ:

       git clone https://github.com/debbyoyinkansolae1b4-stack/lct2026-dispatcher.git dispatcher && cd dispatcher
       sudo docker build -t dispatcher .

3. Запустите контейнер в фоне. Он будет сам подниматься после сбоя и после перезагрузки сервера:

       sudo docker run -d --name dispatcher --restart unless-stopped -p 80:8000 dispatcher

   Приложение откроется по адресу `http://<адрес сервера>`. Если на сервере включён межсетевой экран, откройте порт 80
   (например, `sudo ufw allow 80/tcp`). После запуска приложение прогревается до минуты; ход запуска виден
   в `sudo docker logs -f dispatcher`.

**За nginx** (свой домен, HTTPS, несколько сайтов на одном сервере). Опубликуйте порт контейнера только на локальном
адресе — `-p 127.0.0.1:8000:8000` вместо `-p 80:8000` — и подключите готовую настройку `deploy/dispatcher.nginx`: как это
сделать, написано в начале файла. В ней увеличено время ожидания ответа. Расчёт плана и сверка с OR-Tools длятся
дольше стандартных для nginx 60 секунд, и без этой настройки ответ оборвётся ошибкой 504.

**Обновление.** Репозиторий хранит одну актуальную версию без истории, поэтому обновляйте его так:

    git fetch origin && git reset --hard origin/main
    sudo docker build -t dispatcher .
    sudo docker rm -f dispatcher
    sudo docker run -d --name dispatcher --restart unless-stopped -p 80:8000 dispatcher

Настройки, изменённые в `/admin`, и добавленные наборы данных хранятся внутри контейнера. Когда контейнер
пересоздаётся, они возвращаются к значениям из репозитория.

### Работа без интернета

Данные задания, координаты адресов, расстояния по дорогам и слои пробок уже лежат в репозитории, поэтому на выданных
данных план считается без интернета. В сеть приложение обращается только в двух случаях: чтобы нарисовать на карте
линию нового маршрута по дорогам (без сети линия будет прямой) и при загрузке своего набора заявок, чтобы найти
координаты адресов и расстояния между ними. Подложка карты тоже загружается из интернета.

## Что посмотреть за пять минут

Кнопка **«?»** в правом верхнем углу запускает интерактивный тур: десять тем по всем возможностям приложения.
Список тем открывается и прямой ссылкой: `/?tour=menu`, на стенде — http://217.60.61.158/?tour=menu. Коротко:

1. **Данные.** Выберите участок вверху: заявки дня сразу видны на карте.
2. **План.** Нажмите «Построить план». Слева появятся маршруты бригад, выполненные заявки, пробег, ожидание аварий,
   сравнение с базовым вариантом из ТЗ и то, сколько бригад из доступных на участке задействовал план.
3. **Объяснение.** Щёлкните по точке на карте: вы увидите, почему заявка у этой бригады, кто ещё мог её взять и во что
   бы это обошлось.
4. **Событие.** В блоке «Событие в течение дня» добавьте аварию, отмените заявку или снимите инженера с линии.
   План перестроится, а приложение покажет, что изменилось.
5. **Сверка с OR-Tools.** Отметьте галочку рядом с кнопкой расчёта: тот же день решат базовый вариант из ТЗ,
   OR-Tools и наш поиск, в одинаковых условиях и с одинаковым временем.
6. **Администрирование** (`/admin`): свои наборы заявок (загрузка файла, генератор, пример файла), пробки, цель
   планирования, нормативы и допущения, состав поиска, анализ и оценка «что будет, если изменить допущение».

## Состав

| Путь | Что там |
|---|---|
| `app.py` | веб-сервер (FastAPI): страницы и программный интерфейс приложения |
| `run.py` | расчёт плана из командной строки |
| `src/` | модель задачи и данные (`data`), построение и проверка плана, перестройка после событий (`plan`), поиск и нейросеть (`search`), скомпилированные ядра поиска (`engine`), отчёты и объяснения (`report`), сверка с OR-Tools (`reference`) |
| `web/` | интерфейс: главная страница, администрирование, тур |
| `config/` | настройки по умолчанию: цель, нормативы, допущения, состав поиска |
| `data/` | обезличенные данные задания, координаты, расстояния по дорогам, слои пробок, пример файла заявок |
| `docs/` | документация (PDF и HTML), интерактивная схема движка |
| `Dockerfile` | сборка образа |
| `deploy/` | настройка nginx для запуска на сервере |
